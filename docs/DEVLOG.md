# WebSim 개발일지

브라우저에서 동작하는 Verilog / SystemVerilog / VHDL 시뮬레이터 **WebSim** 을 만들고, 합성 → FPGA 배치 배선 →
교육용 ASIC 레이아웃까지 확장한 과정을 기록합니다. 커밋·이슈 번호는 저장소
[infinity9753/websim](https://github.com/infinity9753/websim) 기준입니다.

- 기간: 2026-10-17 ~ 2026-11-04
- 커밋 76개, 이슈 55개(모두 종료)
- 규모(시점에 따라 바뀌므로 확인은 `npx vitest run`, `npx playwright test --list`, `wc -l`): TypeScript 약 2만 줄(`src/`), 단위 테스트 약 250개, 브라우저(E2E) 테스트 11개 (#56~#61 시점)
- 배포: GitHub Actions 에서 테스트 → 빌드 → E2E → GitHub Pages

## 1. 출발점과 원칙

**목표**: 데스크톱 HDL 시뮬레이터의 익숙한 작업 흐름(`vlib → vlog/vcom → vsim → add wave → run`)을 그대로 웹에서
제공하는 것. 서버 없이 정적 사이트로 배포하고, 시뮬레이션은 전부 브라우저 안에서 수행합니다.

**클린룸 원칙** (`CLAUDE.md`, `docs/SPEC.md`)
- 상용 시뮬레이터의 코드·문서·메시지·자산은 쓰지 않는다. 근거는 직접 작성한 기능 명세 `docs/SPEC.md`, 공개된
  시뮬레이터 동작 지식, IEEE 1364 / 1800 / 1076 표준.
- `** Error: file(line): ...`, `(vsim-3170)` 같은 메시지 형식은 기존 스크립트와의 호환을 위해 공개적으로 보이는
  출력 형식만 따른다.
- 외부 오픈소스(Yosys, nextpnr, Pyodide, OpenTPU 등)는 라이선스를 확인하고 출처를 README 에 밝힌다.

**작업 방식**
- 기능 하나 = 커밋 하나. 제목은 명령형, 본문에 무엇을·왜.
- 모든 동작 변경에는 테스트(엔진은 Vitest, UI 는 Playwright).
- 할 일은 GitHub 이슈로 등록하고 번호 순서대로 처리, 커밋에 `Fixes #N` / `Refs #N`.

**기술 선택**: TypeScript, Vite, CodeMirror 6, Vitest, Playwright. 백엔드 없음.

### 핵심 설계

- **값 표현**: `Vec` 는 BigInt 두 평면(a/b)으로 0·1·X·Z 를 표현하고, VHDL `std_logic` 의 U/W/L/H 를 위한 u/k 평면을
  추가로 가집니다. 폭 제한이 없고 Verilog 크기·부호 규칙을 따릅니다.
- **커널**: 신호마다 전체 값 이력을 저장(나중에 파형에 추가한 신호도 처음부터 보임). active / inactive / NBA /
  postponed 영역, 델타 사이클, 다중 구동 해석(resolution), force.
- **정교화 = 컴파일**: AST 를 해석하지 않고 식·문장을 JavaScript 클로저로 한 번 컴파일해 실행합니다. 프로세스는
  제너레이터(대기 지점이 있는 경우) 또는 콜백으로 돌아갑니다.
- **언어 공통 AST**: Verilog 와 VHDL 프런트엔드가 같은 AST 를 만들어 혼합 언어 인스턴스화가 자연스럽게 됩니다.

### 초기 버그

- `e4fd7fb`: 하위 모듈의 `output reg` 가 상위 넷과 합쳐질 때 초기값이 Z 로 남던 문제, 새 `vsim` 때 파형 목록이 남던 문제.

## 4. 3단계 — 성능: 커널 2배, 숫자 빠른 경로 (#30)

### 1차 (`b3363db`) — 커널 구조 개선, 약 2배

- `always @(...)`, `always @*`, VHDL 감도 목록 프로세스를 제너레이터 대신 **지속 리스너 위의 콜백**으로 실행.
  브레이크포인트·단계 실행 중에는 훅이 걸린 제너레이터로 되돌아가 디버깅은 그대로 동작.
- 파형 이력의 작은 확정 값은 객체 대신 숫자로 저장 → GC 시간 23% → 6%.
- 값 변경마다 리스너 집합을 복사하지 않고, 벽시계 확인은 256 시간 단계마다.
- `bench/lfsr.ts` 벤치마크: **168k → 343k 사이클/초**(훅 없음), 160k → 329k(디버그 훅, UI 기본).

### 2차 (`c52b63a`) — 2값 숫자 빠른 경로, 누적 약 3.2배

- 32비트 이하 식에 `nk()` 평가기를 붙여 JS 숫자로 계산하고, 피연산자에 X/Z(U/W/L/H)가 있으면 -1 을 돌려
  기존 4값 BigInt 경로로 다시 계산 → **의미는 그대로**.
- 상수 지연은 한 번만 계산, posedge/negedge 판정·커밋 비교·이력 저장에 캐시된 숫자 사용, 시간 버킷 배열 재사용.
- 측정: #30 이전 커밋과 같은 머신에서 번갈아 측정해 **약 3.2배(2.8~3.6배)**. 측정 잡음이 커서 git worktree 로
  이전 버전을 띄워 교대로 재는 방법을 썼습니다.
- **차등 테스트**: 무작위 식 설계 40개(폭·부호·X/Z·32비트 초과 혼합)를 빠른 경로 켜고/끄고 실행해 출력이 같아야 통과.

**찾은 버그**: 커밋 비교에서 아직 계산되지 않은 캐시(`_n = -2`)를 쓰던 실수. 이전 값이 빠른 경로가 아닌 연산에서 온
경우를 일부러 만드는 테스트로 재현해 고쳤습니다.

## 6. 5단계 — Yosys 논리 합성 (#47)

`44918b4`

- `synth [-top m] [-target generic|ice40|ecp5|gowin|xilinx] [-flatten] [files]`. Yosys 를 시뮬레이션 워커 안에서
  동적 import 로 불러와 약 77 MB 의 WebAssembly 는 처음 쓸 때만 내려받습니다(진행률 표시).
- 파일을 생략하면 라이브러리에서 최상위와 그 하위 모듈의 소스를 찾고, `-top` 이 없으면 테스트벤치가 아닌 최상위
  (또는 테스트벤치가 인스턴스화한 모듈)를 고릅니다.
- 합성 창: 셀 사용량 표, Yosys JSON 넷리스트로 그린 회로도(논리 깊이로 열 배치, 플립플롭에서 루프 끊기),
  generic 넷리스트를 `work` 에 컴파일해 같은 테스트벤치로 게이트 레벨 시뮬레이션.
- 테스트: 카운터의 합성 넷리스트가 RTL 과 똑같이 시뮬레이션되는지.

**겪은 문제**: 폴더 경로는 중첩 트리로 넘겨야 했고, 로그의 ANSI 색 코드를 제거해야 했으며, `stat` 파서는 "cells"
줄 다음 행만 읽도록 고쳤습니다. Vite 워커는 동적 import 를 위해 ES 모듈 형식으로 바꿨습니다.
VHDL 합성은 YoWASP 에 GHDL 플러그인이 없어 지원하지 않습니다.

## 7. 6단계 — FPGA 배치 배선: iCE40 (#48), ECP5·Gowin (#50)

### iCE40 (`00b0a5d`)

- `pnr` 명령: `synth -target ice40 -flatten` → nextpnr-ice40 → icepack. 도구는 약 235 MB 로 처음 쓸 때 내려받습니다.
- 핀 제약은 `-pcf` 또는 프로젝트의 `<top>.pcf`. 자원 사용률, 클록별 최대 주파수(목표 대비 PASS/FAIL), 타이밍
  실패 시 명령 실패.
- 배치 배선 창: 디바이스·패키지·PCF·클록 선택, 사용률 표, **SVG 플로어플랜**(사용된 타일과 타일 간 연결),
  PCF 템플릿 생성, `.bin` 다운로드.
- **겪은 문제**: nextpnr 의 SVG 출력 옵션은 474초가 걸려 쓰지 않고 `placed.json` 을 직접 그렸습니다. 타이밍
  실패에도 결과를 받으려면 `--timing-allow-fail` 이 필요했고, 도구가 돌려주는 파일은 `Uint8Array` 라 디코딩이
  필요했습니다.

### ECP5 와 Gowin (`3cfb356`)

- 디바이스 표에 계열(ice40/ecp5/gowin)을 두고, 계열이 Yosys 타깃·nextpnr 빌드·제약 형식·패커를 결정:
  - iCE40: `.pcf` → icepack → `.bin`
  - ECP5 (LFE5U-12F~85F): `.lpf` → ecppack → `.bit` (+ `.config`)
  - Gowin (Tang Nano 1K/4K/9K/20K): `.cst` → gowin_pack → `.fs`
- **gowin_pack 문제**: Gowin 패커(Apicula)는 Python 프로그램이라 YoWASP 가 Pyodide 위에서 돌리는데, 의존성을
  micropip 으로 Pyodide CDN 에서 받습니다. 작업 환경에서는 CDN 이 막혀 있었고, 원칙적으로도 제3자 런타임 의존은
  피하고 싶었습니다. 해결:
  - `loadPyodide` 옵션으로 **우리 Pyodide 로더**를 넘김
  - PyPI 에서 Pyodide 314 ABI 용 `msgspec` WebAssembly 휠(137 KB, BSD-3)을 받아 `vendor/` 에 넣고 sha256 기록
  - micropip 대신 도구 안의 Apicula 휠을 푸는 작은 대체 모듈
- `synth_gowin` 은 `-flatten` 옵션을 거부해(항상 평탄화) 해당 타깃에서는 빼도록 고쳤습니다.
- Gowin 은 모든 포트에 핀이 있어야 하므로 "Unconstrained IO" 오류에 템플릿 안내를 덧붙였습니다.
- Pages 배포 크기 약 650 MB(계열별 도구는 첫 사용 때만 내려받음).

## 9. 8단계 — 브라우저 안의 교육용 ASIC 흐름 (#51)

OpenROAD/Magic 같은 실제 ASIC 도구와 PDK 는 브라우저에서 돌릴 수 없어, **가상의 셀 라이브러리와 층 구성**으로 전 과정을
직접 구현했습니다. 학습·시각화용이며 제조용이 아닙니다. 6개 커밋으로 나눠 진행했습니다.

### 8.1 표준 셀 라이브러리와 합성 (`b37d1b8`)

- `websim_edu`: INV, BUF, NAND2/3, NOR2/3, AND2, OR2, XOR2, XNOR2, AOI21, OAI21, MUX2, DFF, DFFR(비동기 리셋),
  TIEHI/TIELO, 필러. 0.4 µm 트랙 격자, 8트랙 행.
- 모든 핀은 자기 트랙 열에 접근점을 가져 배선기가 M2 에서 via1 으로 내려가 닿을 수 있게 설계.
- Liberty(면적·지연) 자동 생성, specify 지연을 가진 Verilog 셀 모델.
- `synth -target asic`: `dfflegalize`/`dfflibmap`/`abc -liberty` 로 매핑. 음의 엣지·enable·set 플립플롭은 DFF/DFFR +
  논리로, 상수는 TIE 셀로, 넷 간 대입은 BUF 로. 래치는 거부.
- **겪은 문제**: Yosys 가 셀의 포트 방향을 몰라 `check` 가 "구동 없음"을 보고 → `read_liberty -lib` 추가.
  `splitnets -ports` 는 `q[3:0]` 를 이스케이프된 스칼라 포트로 바꿔 테스트벤치와 맞지 않게 되어 제거.
- **오해를 바로잡은 일**: 게이트 레벨 결과의 시각이 RTL 과 다르게(`22` 대신 `22000`) 찍혀 버그로 의심했으나,
  `%t` 는 표준대로 시뮬레이션 정밀도(셀 모델의 1ps)로 표시되는 것이었습니다. 테스트를 `$time` + `%0d` 로 고쳤습니다.

### 8.2 플로어플랜과 배치 (`636ea3f`)

- 사용률로 정한 정사각형 코어, N/FS 가 번갈아 놓이는 행(전원 레일 공유), 코어 둘레 4트랙 여백.
- IO 핀: 처음엔 입력 왼쪽·출력 오른쪽, 이후 연결된 셀의 무게중심 각도에 따라 재배치.
- 전역 배치: 이차(quadratic) 배치를 축마다 야코비 전처리 켤레 기울기법(CG)으로 풀고, SimPL 방식의 확산 앵커를
  반복적으로 강화.
- 합법화: y 순서로 행 채우기 + 행 안에서 **Abacus**(제곱 변위 최소). 세부 배치: HPWL 이 줄어드는 동안 빈칸 이동과
  인접 교환. 남은 칸은 필러.
- 측정: 154셀 ALU 배치 0.15초, **HPWL 이 무작위 합법 배치의 0.36배**.

### 8.3 배선 (`d77fa87`)

- 다이 전체의 3차원 트랙 격자(M2·M4 가로, M3·M5 세로, 2~4층). 반대 방향 이동과 비아에 비용.
- 넷마다 A* 로 트리를 키우고(트리 전체에서 가장 가까운 미연결 단자로), **PathFinder 협상 혼잡** 방식으로 과사용
  지점을 가진 넷을 뜯어 다시 배선.
- 전원: M1 레일 + 좌우 여백의 M3 스트랩, 스트랩의 비아 지점은 막아 둠. 좌우 IO 슬롯을 홀수 트랙으로 옮겨 전원 비아
  (짝수 트랙)와 겹치지 않게 함 — 2층 배선에서도 좌측 포트가 코어로 들어갈 수 있도록.
- **독립 검증기** `verifyRouting`: 형상만 보고 단락(전원 포함)·개방을 찾음. 일부러 넣은 단락·개방을 잡는지도 테스트.
- 측정: 154셀 ALU 0.17초·8회 반복·HPWL 의 1.19배, 2층에서도 깨끗. **1,647셀 16×16 MAC 2.1초**에 단락·개방 없음.

### 8.4 레이아웃, DEF/LEF/GDSII, 타이밍 (`7677131`)

- 셀 레이아웃 생성: N웰, 확산, 입력마다 폴리 핑거, 공유 M1 레일과 콘택트, M1 핀 패드.

### 8.5 레이아웃 창 (`760004a`)

## 10. 9단계 — FPGA 넷리스트 게이트 레벨 시뮬레이션 (#52)

`4bbe5f2` — "FPGA 타깃도 게이트 레벨 시뮬레이션 되게" 요청.

### 방법

- Yosys 가 함께 배포하는 기본 소자 시뮬레이션 모델 `cells_sim.v`(ISC)를 사용. 저장소에 복사하지 않고 **Vite 플러그인이
  빌드 때 설치된 `@yowasp/yosys` 의 리소스 tar 에서 직접 읽어** 가상 모듈로 제공(워커 번들에도 적용).
- 합성 시 `synth/<타깃>_cells.v` 로 써 두고(인클루드 펼침, `` `timescale 1ps/1ps `` 머리말), "넷리스트 시뮬레이션"이
  함께 컴파일.
- Yosys 에 블랙박스만 있는 DSP(ECP5 `MULT18X18D`, Gowin `MULT9X9/18X18/36X36`)는 블랙박스 선언을 그대로 가져와
  Yosys 가 쓰는 조합 곱셈 모드의 동작을 붙이고, 레지스터 모드는 정교화 시점 `$error`.
- Yosys 넷리스트는 모듈 파라미터를 버려 `#(.WIDTH(4))` 를 쓰는 테스트벤치가 로드되지 않음 → 최상위에 합성 때 쓴
  값으로 파라미터를 다시 선언(`parameter_default_values`).

### Yosys 모델을 돌리며 드러난 WebSim 결함 (모두 수정)

1. **속성 `(* ... *)`** 를 렉서가 몰랐음 → 건너뛰되 `@(*)` 는 유지.
2. **case-generate** 미지원 → `===` 비교의 if-generate 연쇄로 변환.
3. **정교화 시점 `$error/$fatal/$warning/$info`** 모듈 항목 미지원 → 선택된 generate 분기에서만 보고.
4. **specify 경로가 많으면 메모리 부족**: 같은 출력으로 가는 경로를 `a > b ? a : b` 로 중첩해 누적식이 경로마다 두 번씩
   복제 → 경로 n개에 2ⁿ 크기. Xilinx `CARRY4`(약 20경로)에서 Node 가 8 GB 를 넘겨 중단. 리터럴은 숫자로 바로 비교하고
   나머지는 균형 트리로 바꿈. (단계별 시간·메모리를 찍어 vsim 단계 → 셀 종류 → specify 로 좁혀 찾음)
5. **`always @*` 가 시간 0 의 상수 연결을 놓침**: 상수 포트 연결·넷 선언 대입의 시간 0 평가가 `always @*` 가 대기를
   시작하기 전에 일어나 Gowin `ALU` 모델 출력이 X 로 남음 → 고정 감도 목록 프로세스는 생성 즉시 대기를 시작.
6. 설계 로드가 실패해도 `vsim` 이 성공을 반환 → 실패 반환.

또 Xilinx 모델의 specify 지연(예: `BUFG 96`, `CARRY4 598`)은 ps 값인데 `timescale` 이 없어 ns 로 해석되어 10 ns 클록에서
아무 것도 전파되지 않았습니다(`timescale` 머리말로 해결). Gowin 은 모델 지연이 실제에 가까워(LUT 하나 약 1 ns) 테스트
벤치의 표본 시점을 늦춰야 했는데, 이는 결함이 아니라 게이트 레벨 타이밍이 제대로 동작한다는 뜻입니다.

**결과**: ice40·ecp5·gowin·xilinx 네 타깃 모두 RTL 과 무작위 입력 40사이클 출력이 같음.

**테스트 자체의 결함**: 기존 합성 E2E 테스트가 넷리스트를 실제로 돌리지 않고도 통과하고 있었습니다(예제 첫 실행의
`$finish` 문구에 걸려서). 이 때문에 파라미터가 있는 예제 테스트벤치로는 generic 넷리스트도 원래 시뮬레이션이 안 되던
것을 몰랐습니다. 이후 `$finish`/`PASS` 줄 **개수**를 세는 방식으로 바꿨습니다.

## 12. 11단계 — 기본 예제 OpenTPU (#55)

`d3923a1`, `0a18139` — "예시 파일로 OpenTPU 를 기본으로, 검색해서 찾을 것".

### 조사

- [UCSBarchlab/OpenTPU](https://github.com/UCSBarchlab/OpenTPU): 구글 TPU 논문을 바탕으로 한 오픈소스 재구현, BSD-3.
  8×8(설정 가능) 시스톨릭 행렬 곱 장치, 가중치 FIFO, 통합 버퍼, 누산기, ReLU/시그모이드 활성화, 명령 7개
  (RHM, WHM, RW, MMC, ACT, NOP, HLT).
- **Verilog 가 아니라 PyRTL(Python HDL)로 작성**되어 변환이 필요.

### 진행 방식 결정

외부 저장소의 Python 코드 실행이 권한 정책에 막혀, 우회하지 않고 사용자에게 두 방법을 물었습니다:
(1) PyRTL 로 원본 그대로 Verilog 생성, (2) 읽기 쉬운 Verilog 로 직접 이식. 사용자가 (1)을 선택했습니다.

### 변환 과정

1. PyRTL 최신판(1.0)에서는 2017년 코드가 돌지 않음(`helperfuncs` 제거). 0.8.x 는 현재 Python 에서 설치 실패.
   **0.10.2** 를 쓰고, 이름만 바뀐 함수 한 줄(`helperfuncs.mult_signed` → `signed_mult`)을 작업 사본에서만 수정.
2. `MATSIZE = 8`(원본 README 의 simplemult 조건)로 원본 하드웨어 시뮬레이션 실행 → 429사이클, 결과 벡터 8개.
   원본 **기능 시뮬레이터**(`sim.py`)도 같은 값(첫 원소 100, 128, 44, 58, 198, 198, 72, 21) → 기준값 확정.
3. `output_to_verilog` 가 이름 없는 포트(`halt` 등) 때문에 실패 → 우리 드라이버에서 파이썬 변수 이름을 붙임.
4. 기본 설정의 누산기는 65,536 × 32비트 × 8개라 브라우저에 무거움 → `config.py` 의 크기 설정만 줄임(명령 512,
   통합 버퍼 256, 누산기 256). 결과·사이클 수 동일 확인.
5. 파형에서 볼 수 있도록 `pc`, `instr`, `dispatch_*`, `rhm_*`/`whm_*`, `mm_busy` 등 주요 신호에 이름 부여,
   최상위 모듈 이름 `toplevel` → `opentpu`. 결과: 약 1만 줄, 395 KB.
6. 재생성 스크립트 `scripts/opentpu_export.py` 를 커밋하고, 다시 실행해 **바이트 단위로 같은** Verilog 가 나옴을 확인.

### 테스트벤치 (`tb_opentpu.v`, 직접 작성)

- 원본 `runtpu.py` 처럼 호스트 메모리와 가중치 DRAM 역할: 한 클록 지연 읽기, 쓰기 반영, 타일 전송.
- **X 결과 문제**: PyRTL 시뮬레이터는 메모리를 0 으로 시작하지만 Verilog 는 X. 이 프로그램의 MMC 는 누산기에 더하기만
  하므로 X 가 퍼짐 → 테스트벤치가 명령 메모리·통합 버퍼·누산기를 0 으로 초기화.
- **확인하다 잡은 실수**: 처음엔 `mem_10`~`mem_17` 도 0 으로 지웠는데, 생성된 코드를 보니 이는 가중치 FIFO 가 아니라
  설계가 스스로 초기화하는 **시그모이드 표**였습니다. 이번 프로그램(ReLU)에는 영향이 없었지만 초기화 순서가 정해지지
  않은 경쟁이라 지우지 않도록 고침.
- 원본의 `rtl_assert` 두 개(행렬 장치·활성화 장치가 바쁠 때 새 명령 금지)는 PyRTL 에서 "조건이 참이면 1"인 출력이라
  테스트벤치가 감시하고 위반 시 실패 처리.
- 결과: **429사이클 HLT, 결과가 원본 두 시뮬레이터와 같아 PASS**. 브라우저에서 앱을 열고 PASS 까지 약 1.2초,
  시뮬레이션 자체 0.31초.

### 함께 고친 시뮬레이터 결함

- **`$write` 가 호출마다 줄을 바꿈**: Session 이 정교화기에 write 콜백을 주지 않아 print 로 대체되고 있었음. 줄 버퍼를
  두어 개행이 올 때 출력하고, 이어지는 `$display` 는 같은 줄을 계속, 실행이 끝나면 남은 내용을 출력.

### 앱 반영

- 395 KB Verilog 는 **필요할 때 불러오는 별도 청크**(397 KB, gzip 69 KB)로 분리해 메인 번들에 넣지 않음.
- 무거운 OpenTPU 대신 합성·P&R·ASIC E2E 테스트는 8비트 CPU 예제로 전환(작업 라이브러리를 비운 뒤 불러와 최상위
  후보가 둘이 되지 않게).
- `opentpu.v` 머리말과 `OpenTPU_LICENSE.md` 에 원본 저작권·라이선스, 생성 방법과 변경점을 기록.
- 배포 사이트(github.io)는 작업 환경의 프록시가 막아 직접 열지 못했고, 같은 커밋의 빌드를 브라우저로 확인하고
  CI 의 빌드·배포 성공을 확인했습니다.

## 13. 12단계 — 타이밍 검사와 SDF 백어노테이션 (#56)

오픈소스 EDA 흐름(OpenROAD/OpenSTA/OpenRCX)을 검토한 뒤 "배치 후 타이밍 시뮬레이션"을 브라우저 안에서 닫기 위해
#56~#59 를 등록했고, 그 첫 단계입니다.

### 타이밍 검사 (IEEE 1364-2005 §15)

- 파서: specify 안의 `$setup $hold $setuphold $recovery $removal $recrem $width $period`. 이벤트는
  `[posedge|negedge] 신호 [&&& 조건]` (`&&&` 는 렉서가 `&&` + `&` 로 자르므로 파서에서 이어 붙임), 한계값은 min:typ:max
  중 typ, 마지막 인자는 notifier.
- 인자 순서가 검사마다 다른 것이 함정입니다. `$setup(data, ref, limit)` 만 데이터가 먼저이고, 나머지는 `(ref, data, ...)`.
- 의미: setup/removal 은 기준 이벤트에서 "직전 데이터 변화가 한계 안에 있었나", hold/recovery 는 데이터 이벤트에서
  "직전 기준 이벤트가 한계 안에 있었나"를 봅니다. `$width` 는 반대 엣지까지, `$period` 는 연속된 기준 엣지 간격.
- 위반은 `** Warning: f.v(7): $setuphold( posedge CLK:17000 ps, D:16000 ps, 2000 ps );` 와 시각·인스턴스 줄로 보고하고,
  notifier 는 x→0, 0→1, 1→0 으로 토글합니다. 셀 모델의 `always @(notifier) Q <= 1'bx;` 가 이를 받아 출력을 X 로 만듭니다.
- 첫 구현에서 위반이 하나도 안 났는데, 이벤트 값을 `final(n, 0)` 으로 0비트로 잘라 엣지를 못 본 탓이었습니다.

### SDF (IEEE 1497)

- `src/engine/sdf.ts`: S-식 파서, `TIMESCALE`, `DIVIDER`, 이스케이프, min:typ:max 선택.
- 경로 지연은 "인스턴스 경로/출력 포트" 키(`/tb/dut/u1/Y`)로 커널에 등록해 두고, SDF 가 값을 넣으면 출력 경로의
  지연 함수가 새 값(상승/하강/턴오프, 출력 값으로 선택)을 읽습니다. 한 출력에 IOPATH 가 여럿이면 최대값.
- TIMINGCHECK 는 같은 스코프의 specify 검사 한계값을 바꿉니다(SETUPHOLD 는 두 값).
- INTERCONNECT/PORT/INCREMENT 와 와일드카드 인스턴스는 경고로 알립니다.
- 진입점: `vsim -sdfmin|-sdftyp|-sdfmax [영역=]파일` 과 `$sdf_annotate("f.sdf", dut, , , "MAXIMUM")`.
- 테스트 작성 중 `$time` 이 모듈 시간 단위(1 ns)로 반올림돼 3.7 ns 가 4 ns 로 보였습니다 — 시뮬레이터가 아니라
  테스트가 틀린 경우라 `$realtime` 으로 바꿨습니다.

### ASIC 흐름과 연결

- 셀 라이브러리: DFF/DFFR 에 setup 0.05 / hold 0.02 ns, DFFR 에 recovery 0.06 / removal 0.03 ns. Liberty 에
  `setup_rising/hold_rising/recovery_rising/removal_rising` 제약 아크, 시뮬레이션 모델에 `$setuphold`/`$recrem` 과 notifier.
- Yosys 스크립트에 `rename -enumerate` 를 넣어 JSON·Verilog 넷리스트·SDF 의 인스턴스 이름(`_123_`)을 일치시켰습니다.
- `asic` 명령이 `asic/<top>.sdf` 를 씁니다: 셀마다 부하(핀 용량 + 배선 길이) 반영 지연의 IOPATH, 플립플롭의 SETUPHOLD/RECREM.
- 검증: 8비트 CPU 를 `asic` 으로 배치·배선한 뒤 `vsim -sdftyp /tb_cpu/dut=asic/cpu.sdf` 로 돌려 경고 없이 RTL 과 같은
  출력·PASS 를 확인합니다.

## 14. 13단계 — 정적 타이밍 분석: SDC, 홀드, NLDM, 보고서 (#57)

이전의 "타이밍 추정"은 셀 지연 = 고유 지연 + 기울기 × 부하, 이상적 클럭 하나, 셋업만 보는 계산이었습니다. 이를 OpenSTA 같은
도구가 하는 방식에 가깝게 다시 썼습니다(`src/engine/asic/sta.ts`, `sdc.ts`). 코드는 공개 문서(Liberty·SDC 형식)와 STA 의
일반 원리로 새로 작성했습니다.

### 지연 계산 (NLDM)

- 셀마다 5×5 표: 입력 전환 시간(0.01–0.6 ns) × 출력 부하(0.001–0.06 pF). 값은 가상의 매끄러운 모델에서 만들어 Liberty 의
  `lu_table_template(delay_5x5)` 와 `cell_rise/cell_fall/rise_transition/fall_transition` 표로 씁니다.
  덕분에 ABC 의 `Templates are not defined.` 알림(남은 과제였음)도 사라졌습니다.
- STA 는 표를 쌍선형 보간(범위 밖은 선형 외삽)합니다. 상승 표가 큰 쪽(셋업), 하강 표가 작은 쪽(홀드)입니다.
- 전환 시간은 위상 순서로 전파합니다. 부하 = 입력 핀 용량 + 배선 길이 × 0.03 fF/트랙 + 출력 포트 부하(`set_load`).
- SDF 의 IOPATH 도 이 계산에서 나오므로, 시뮬레이션·SDF·STA 가 같은 지연을 씁니다.

### SDC

- Tcl 의 작은 부분집합을 직접 해석합니다: 단어, `{}`, `""`, `[명령]`, `set`/`$변수`, 줄 끝 `\`.
- `create_clock`, `set_input_delay`/`set_output_delay` (`-clock -max -min`), `set_load`, `set_input_transition`,
  `set_clock_uncertainty`, `set_false_path`, `set_max_delay`, `set_min_delay`, 객체 함수 `get_ports`(버스 이름이 비트를 고름,
  글롭) 등. 모르는 명령과 맞는 객체가 없는 패턴은 줄 번호와 함께 경고합니다.
- 테스트를 쓰다 `-max 0.3 -min 0.01` 을 한 명령에 썼는데, 이것은 SDC 문법이 아니었습니다(최대·최소는 명령을 나눠 씀).
  틀린 쪽은 테스트였고, 대신 남는 인자를 경고하도록 했습니다.

### 분석

- 시작점: 클럭이 닿는 플립플롭(클럭 핀에서 BUF/INV 를 거슬러 `create_clock` 포트까지), 입력 지연이 있는 입력 포트.
  끝점: D(셋업/홀드), RN(복구/제거), 출력 지연이 있는 출력.
- 도착 시각은 발사 클럭별로 전파합니다. 서로 다른 클럭 사이는 발사·포착 에지 쌍 중 가장 가까운 것으로 셋업 관계를,
  그 한 주기 앞을 홀드 관계로 씁니다.
- 예외: `-from` 에 점(포트·셀·핀)이 있는 예외는 그 시작점만으로 따로 전파하고, 클럭이나 `-to` 만 있는 예외는 끝점에서
  맞춰 봅니다. false path 가 max/min delay 보다 우선합니다. `-through` 는 경고 후 무시.
- 결과: WNS/TNS, WHS/THS, 클럭별 가능 주파수, 클럭 없는 플립플롭, 제약 없는 포트, 경로 보고서(핀마다 증분·누적·전환·부하,
  필요 시각, 여유 MET/VIOLATED).
- 제약이 없을 때(`asic` 기본)는 모든 플립플롭에 이상적 클럭 하나를 두고 같은 엔진으로 예전 형식의 임계 경로를 냅니다.

### 사용

- `asic -sdc cpu.sdc` (레이아웃 창에도 SDC 파일 칸), `sta [-sdc f] [-paths n] [-setup|-hold]`, `asic/<top>_sta.rpt`.
- 8비트 CPU 예제에 `cpu.sdc`(4 ns 클럭)를 넣었고, 셋업·홀드 모두 위반 없이 통과하는 것을 테스트합니다.
- 테스트는 손으로 만든 넷리스트(FF → INV → INV → FF)에서 표를 직접 찾아 계산한 값과 STA 결과를 비교합니다.

## 15. 14단계 — RC 추출과 SPEF (#58)

OpenRCX 가 하는 일을 교육용으로 줄여 구현했습니다(`src/engine/asic/rc.ts`).

- **RC 망**: 배선의 트랙 교차점마다 노드를 두고, 한 트랙 = 저항 하나 + 양 끝에 용량 절반. 비아는 저항, 셀 입력 핀은 핀 용량.
  층 상수는 가상의 값입니다: M2/M3 시트 저항 0.4 Ω/□, M4/M5 0.15 Ω/□(선폭 = 반 피치라 한 트랙 = 2 □),
  면적 용량 40/25 aF/µm², 가장자리 40/35 aF/µm, 비아 2–6 Ω. 이웃 선과의 결합 용량은 다루지 않습니다.
- **Elmore 지연**: 구동점에서 너비 우선으로 신장 트리를 만들고, 하류 용량을 아래에서 위로 모은 뒤
  `지연(n) = 지연(부모) + R × 하류 용량` 을 위에서 아래로 계산합니다(Ω × fF = 10⁻⁶ ns).
- **STA 반영**: 부하는 추출한 배선 용량을 쓰고, 입력 핀마다 배선 지연을 더하며 전환 시간을
  `√(s² + (ln 9 · d)²)` 로 늘립니다. 경로 보고서에서 입력 핀 줄의 증분이 배선 지연입니다.
- **SPEF**(IEEE 1481): 이름 맵, 포트, 넷마다 `*D_NET 총용량`, `*CONN`(구동 셀 `*D`, 입력 핀 `*L`), `*CAP`, `*RES`.
- **SDF**: WebSim 의 SDF 리더는 INTERCONNECT 를 읽지 않으므로(입력 포트가 상위 넷에 합쳐져 있어 지연을 넣을 곳이 없음)
  구동 셀의 IOPATH 에 그 넷의 최대 배선 지연을 더해 씁니다. 보수적인 근사입니다.
- **함정**: 처음엔 배선 하나를 저항 하나로 봤는데, 라우터가 일직선 배선을 합쳐서 내놓아 중간에 붙은 비아가 망에서 떨어져
  모든 지연이 0 이었습니다. 트랙마다 노드를 두도록 바꿨습니다.
- 크기: 8비트 CPU 에서 배선 용량 약 360 fF, 저항 약 1.2만 개, 최악 배선 지연은 clk 넷 약 14 ps(이상적 클럭이라 STA 에서는
  클럭 넷 지연을 쓰지 않음). 데이터 넷은 1 ps 미만으로 셀 지연(수십 ps)보다 훨씬 작습니다 — 작은 칩에서는 실제로도 그렇습니다.

## 16. 15단계 — OpenLane 프로젝트 내보내기 (#59)

브라우저 안의 교육용 흐름과 실제 제조 가능한 흐름 사이의 다리입니다. OpenROAD·Magic·실제 PDK 는 브라우저에서 돌릴 수
없으니(#49 의 B안 보류 사유), 대신 사용자가 자기 컴퓨터의 OpenLane 2 / LibreLane 에서 바로 돌릴 수 있는 프로젝트를 만듭니다.

- `openlane` 명령: 합성과 같은 방식으로 최상위와 계층의 소스를 모아 `openlane/<top>/` 에 `config.json`(OpenLane 2 형식,
  `dir::` 경로), `src/`, `<top>.sdc`, README 를 쓰고, 같은 내용의 zip 을 만듭니다.
- 클럭 추정: SDC 의 `create_clock` → 없으면 소스에서 `posedge/negedge` 에 가장 많이 쓰인 입력(이름이 clk 류면 동점에서 이김).
  클럭이 없으면 `CLOCK_PORT` 는 null, SDC 는 가상 클럭.
- 기본 SDC: 불확실성 0.25 ns, 입출력 지연 = 주기의 20%, sky130 HD 부하(0.0334 pF)와 전환 시간. 우리 SDC 리더로도 읽힙니다.
- zip 은 의존성 없이 직접 씁니다(`src/engine/zip.ts`: 무압축 저장, CRC-32, UTF-8 이름). 테스트에서 되읽고, Python
  `zipfile` 과 `unzip -t` 로도 확인했습니다.
- UI: **컴파일 ▸ OpenLane 로 내보내기 (sky130)** 가 명령을 실행하고 zip 을 내려받습니다(E2E 에서 확인).

## 18. 배운 점

1. **"통과"를 의심하기**: E2E 가 이전 출력의 문구에 걸려 실제 기능 없이 통과하던 사례가 있었습니다. 결과는 문구가 아니라
   개수·값으로 확인해야 합니다.
2. **테스트와 시뮬레이터가 다르면 누가 맞는지부터**: `%t` 단위, `always @*` 시간 0 경쟁, 모델 지연의 단위처럼 처음엔 버그
   같아 보여도 표준을 확인하면 테스트가 틀린 경우와 시뮬레이터가 틀린 경우가 갈렸습니다.
3. **실제 외부 코드가 최고의 테스트**: Yosys 셀 모델과 OpenTPU 를 돌리면서 속성, case-generate, 정교화 `$error`,
   지수적 specify 식, `$write` 같은 결함이 한꺼번에 드러났습니다.
4. **측정한 뒤 결정**: 커널 최적화, 배치 확산 실험(되돌림), Xilinx 메모리 부족 추적 모두 숫자로 판단했습니다.
5. **원칙과 편의가 부딪칠 때는 묻기**: 서버 백엔드 여부(B안 보류), 외부 코드 실행(OpenTPU) 같은 결정은 사용자에게
   선택지를 제시해 정했습니다.
6. **제3자 의존은 빌드 시점으로**: Yosys 셀 모델은 설치된 패키지에서 빌드 때 읽고, Gowin 패커의 의존성은 저장소에
   고정해 런타임 CDN 의존을 없앴습니다.

## 19. 남은 과제

- **실제 ASIC 흐름(#49 의 B안)**: OpenROAD + Magic + 실제 PDK 는 WebAssembly 빌드가 없어 서버 백엔드가 필요. 보류 —
  대신 `openlane` 내보내기(#59)로 사용자 컴퓨터에서 돌릴 수 있게 함.
- **타이밍 확장**: 클럭 트리 지연(전파 클럭), 결합 용량, SDF INTERCONNECT(입력 포트 지연), 다중 코너.
- **UVM**: 제약 기반 랜덤화(해 찾기), covergroup 등 SystemVerilog 기능이 더 필요. 보류.
- **VHDL 합성**: YoWASP 에 GHDL 플러그인 빌드가 없음.
- **OpenTPU 확장**: 원본의 Boston housing 회귀 예제(MATSIZE 16)나 시그모이드 활성화를 쓰는 프로그램을 추가 예제로.
